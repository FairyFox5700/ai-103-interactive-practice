1. What Is Azure AI Video Indexer?

Azure AI Video Indexer (VI) is a cloud AI service (part of Azure AI services) that extracts deep, structured insights from video and audio content using a pipeline of 30+ AI models — built on top of Face, Azure AI Vision, Speech, Translator, and generative AI/LLM models. It turns unstructured media into searchable, structured JSON metadata.

Two Deployment Options

OptionDescription
Cloud-based Video IndexerWeb app/API, part of Azure AI services. Upload or point to a video; VI indexes it in the cloud. This is the primary option tested on AI-103.
Video Indexer enabled by Azure ArcRuns on Azure Arc-enabled Kubernetes at the edge for low-latency/live streams or data-residency needs (can't move data to the cloud). Supports live video streams and uploaded files on-premises.

Core Capability Themes

  • Visual insights: face detection, celebrity/person recognition, labels (objects/actions), object detection, observed people, OCR (on-screen text), scenes/shots/keyframes, clapper board & color bar detection (post-production).
  • Audio insights: transcription, translation, spoken-language identification (50+ languages), keyword extraction, named entity extraction, audio effects (laughter, applause, sirens), text-based sentiment/emotion detection, speaker diarization.
  • Aggregated/inferred insights: topics inference, brands detection, video summarization using generative AI.
VI is NOT a single model — it's an orchestration layer that runs many Azure AI services models together and merges the results into one unified JSON insight document per video.
Must know: Azure AI Video Indexer is built on Face, Azure AI Vision, Speech, and Translator services — understand it as a composition/orchestration of existing Azure AI services, not a standalone model.

2. Account Types (ARM vs. Classic)

An Azure AI Video Indexer account = the Video Indexer resource that connects your deployment to your Azure subscription for access control, billing, and monitoring.

Account TypeNotes
ARM-based account (current/recommended)Created as a standard Azure resource via the Azure portal ("+ Create a resource" → Azure AI Video Indexer). Managed like any Azure resource: resource groups, RBAC, Azure Policy, managed identity (system- or user-assigned), tags, ARM templates/Bicep. Requires linking a Standard General Purpose v2 storage account. Can optionally connect an Azure OpenAI resource for generative AI features (e.g., summarization).
Classic account (legacy)Older account model created directly through the Video Indexer web portal, not natively an ARM resource. Microsoft's guidance is to migrate/connect classic accounts to ARM-based accounts for full Azure governance (RBAC via Entra ID, monitoring, managed identity) — classic accounts lack these integrations.
Trial accountFree, no Azure subscription required, cloud-based only — good for the web portal demo, but the API cannot be used with a trial account; you must create a paid/standard account to call the REST API.

Creating an Account — Required Fields

  • Subscription, Resource group, Resource name, Region
  • Storage account (Standard GPv2) — mandatory, stores source media and artifacts
  • Optional Azure OpenAI resource connection (for generative AI insights like summaries)
  • System-assigned and/or user-assigned managed identity (needed to access the storage account securely)

Permissions Needed to Create the Resource

  • Subscription-level Owner, OR both Contributor + User Access Administrator roles
Responsible AI gate: Face identification, face customization (Person models), and celebrity recognition are Limited Access features — available only to Microsoft-managed customers/partners who apply via the Face Recognition intake form. Don't assume these are open to every subscriber.
Must know: New/production deployments should use an ARM-based account (full Azure RBAC, managed identity, monitoring integration); classic accounts should be migrated to ARM. The REST API requires a paid ARM/standard account — trial accounts are portal-only.

3. Upload / Index Workflow

The basic lifecycle for processing a video through VI:

  1. Create an Azure AI Video Indexer (standard/ARM) account linked to a storage account.
  2. Upload a media file — two supported methods:
    • Upload to a URL (recommended): a public URL or a SAS URL to a blob in Azure Storage; if storage is behind a firewall, pass useManagedIdentityToDownloadVideo so VI's managed identity can fetch it.
    • Send the video as a byte array in the request body.
  3. Index — choose indexing options: language(s), indexing preset (standard/advanced/basic, audio-only), privacy (private/public), and optional custom model IDs (person model, language model, brands model) and advanced post-production options (clapper board, color bars).
  4. VI runs the multi-model pipeline asynchronously; poll the index/processing state until Processed.
  5. Consume results: retrieve the JSON insights via API, view them in the web portal, or embed widgets (Insights/Player/Editor) in your own app.
  6. Optionally re-index a video later (e.g., after adding a new person to a Person model, or enabling a new insight type) to regenerate/update insights.
You can't use the Video Indexer API with a trial account — automation/CI pipelines require a standard (paid/ARM) account and API subscription keys from the API developer portal.
Must know: The recommended upload method is a SAS URL to Blob Storage (not embedding bytes) — for firewall-protected storage accounts, use the useManagedIdentityToDownloadVideo parameter so VI can authenticate via managed identity instead of a public endpoint.

4. Insights Catalogue (30+ AI Models)

When a video is indexed, VI runs 30+ models and returns a single JSON with time-ranged insight instances. Group them into visual, audio, and inferred/aggregated categories:

Visual Insights

InsightWhat it detects
Face detectionDetects & groups faces; names recognized/celebrity faces; shows % of video appearance.
Labels identificationObjects/actions (e.g., "sunglasses", "swimming") across 50+ translatable categories.
Object detectionSpecific objects: cars, handbags, backpacks, laptops, etc.
Observed people / matched facesDetects people by appearance (clothing) and timeframe, matches to known faces.
OCRExtracts on-screen text (signs, product labels, captions).
Scenes, shots, keyframesScene = event with related shots; shot = frames between visual cuts; keyframe = best representative frame of a shot.
Clapper board / digital patterns (color bars)Post-production metadata (scene/take/roll) — opt-in via Advanced settings at indexing time.

Audio Insights

InsightWhat it detects
Transcription / translation / language IDSpeech-to-text + translation across 50+ languages; auto language identification.
Keyword extractionImportant keywords from single- or multi-language audio.
Named entitiesNLP over transcript + OCR text to find people, locations, brands.
Audio effects detectionClassifies acoustic events: laughter, crowd reaction, alarms, sirens.
Text-based emotion detectionClassifies transcript sentences as anger / fear / joy / sad / none.
SpeakersSpeaker diarization — who said what and when.

Inferred / Aggregated Insights

  • Topics inference — derived from transcript + OCR + recognized celebrities.
  • Brands detection — identifies company/product/service mentions (speech or visual text) from the Bing brands database, customizable with include/exclude lists.
  • Sentiments — aggregated positive/negative/neutral over time ranges.
  • Video summarization — generative-AI-produced textual summary of the video (requires connected Azure OpenAI resource).
Must know: Every insight is returned as time-ranged "instances" inside the JSON — this is how VI lets you jump directly to the moment in a video where a face, keyword, brand, or emotion occurs, which is the basis of "deep search" scenarios.

5. JSON Output Structure

Indexing produces one consolidated JSON document per video (the "Video Indexer JSON" / insights schema). Key top-level concepts to recognize for the exam:

  • Summarized insights vs. detailed insights — summarized = aggregated totals (e.g., list of unique faces, keywords); detailed = per-instance time ranges with start/end timestamps.
  • Each insight type (faces, keywords, labels, sentiments, topics, brands, transcript, OCR, speakers, emotions, scenes/shots/keyframes) appears as its own JSON node, each containing an instances[] array with start/end timecodes.
  • The JSON can be retrieved via the Get Video Index REST API call and is the artifact typically pushed into a search index (e.g., Azure AI Search) or used to ground LLM prompts.
You don't need to memorize every JSON field name for AI-103 — know that VI's output is a structured, queryable JSON you can pass downstream (to Azure AI Search, a database, or an LLM as grounding context) rather than needing to parse raw video yourself.
Must know: Insight JSON separates summarized (aggregate) data from detailed, time-stamped instances — the time-stamped instances are what enables "jump to moment in video" search and retrieval experiences.

6. Widgets for Embedding

VI supports embedding three widget types directly into your own web app via iframe-style URLs — no need to build your own UI from the JSON:

WidgetPurpose
Insights widgetRenders all visual insights (people, keywords, labels, sentiments, emotions, topics, transcript, OCR, speakers, scenes, named entities, objects, etc.). Configurable via URL params: widgets= (which insight panels to show), controls= (search, download, presets, language), language=, locale=, tab=, search=.
Player widgetEmbeds just the video player (with optional insight overlays) without the full insights panel.
Editor widgetEmbeds an editing experience allowing manual correction/refinement of insights (e.g., fixing a mislabeled face or transcript line).
Example URL pattern: https://www.videoindexer.ai/embed/insights/<accountId>/<videoId>/?widgets=people,keywords&controls=search,download
Must know: The three embeddable widget types are Insights, Player, Editor — use the Insights widget when you want a ready-made UI over the extracted metadata without writing custom JSON-rendering code.

7. Custom Models (Content Model Customization)

VI lets you tailor its default AI models to your domain. Three customizable model types:

Person (Face) Model

  • Pairs a person's name with sample face images so VI recognizes that person in future (and re-indexed) videos.
  • You can create multiple Person models per account (e.g., one per channel/show).
  • Limits: up to 1 million people per model, 50 person models per account.
  • Assign a specific person model ID at upload/index/reindex time; if omitted, VI uses the account's default person model.
  • Gated under Responsible AI Limited Access — requires application/approval, available only to Microsoft-managed customers/partners.

Brands Model

  • Detects brand mentions in speech/visual text, informed by Bing's brands database.
  • Customize by: toggling Bing-suggested brand detection on/off, adding an Include list (custom brands not in Bing, each with name/category/description/reference URL), and an Exclude list (suppress unwanted brand matches).
  • Custom brand model is scoped to the account where it was created (not shared across accounts).
  • If you add a brand after indexing, you must re-index the video (Advanced options → Brand categories → All brands) to pick it up.

Language Model

  • Customizes speech-to-text recognition for domain-specific vocabulary (jargon, product names, acronyms) to improve transcription accuracy, similar in spirit to Custom Speech in Azure AI Speech.
All three customization types (Person, Brands, Language) are managed from Content model customization in the Video Indexer web portal, or equivalently through the REST API.
Must know: There are exactly three customizable content models — Person, Brands, Language — and Person/celebrity-recognition features require explicit Limited Access approval due to Responsible AI restrictions (don't expect them enabled by default on a new account).

8. API / SDK Integration Pattern

  1. Create a standard (paid) Video Indexer account — trial accounts cannot call the API.
  2. Sign in to the API developer portal (api-portal.videoindexer.ai) with the account; copy the primary/secondary subscription keys from your Profile → Subscriptions.
  3. Call Get-Account-Access-Token to obtain a short-lived ARM-authenticated access token, then use that token for subsequent calls (upload, get-index, re-index, get-insights, customize models, etc.).
  4. Use official code samples (Azure-Samples/azure-video-indexer-samples) for language-specific authorization flows (.NET, Python, etc.).
  5. Typical calls: Upload Video (URL or byte array), Get Video Index (poll for processing state / retrieve JSON), Get Video Index by language, re-index, and model-customization endpoints (Person/Brands/Language).
Because ARM-based accounts integrate with Microsoft Entra ID and Azure RBAC, production apps typically call the Azure Resource Manager control-plane APIs first to obtain an account access token, then call the VI data-plane REST API with that token — this two-step auth flow is a common exam trap vs. the old classic-account API-key-only model.
Must know: You cannot call the Video Indexer API with a trial account — API access requires a standard/paid account plus subscription keys obtained from the API developer portal, and calls are authorized with a short-lived account access token.

9. Integration Scenarios & RAG Grounding

  • Deep/semantic search: push extracted insights (transcripts, keywords, faces, topics) into Azure AI Search as an index, enabling users to search "moments" inside videos, not just filenames.
  • Content moderation: use detected labels/OCR/transcript to flag inappropriate content (note: automated moderation review isn't available in Azure Government).
  • Accessibility & localization: auto-generated captions/subtitles via transcription + translation insights.
  • Monetization/contextual advertising: use brand and topic insights to match ads to video segments.
  • RAG grounding for LLM/agent apps (AI-103 relevance): feed VI's structured JSON insights (transcript chunks, topics, summaries, entities) as grounding context into a prompt or vector store so an agent can answer questions about video content, cite the exact timestamp, or generate a highlight reel — this is the direct tie-in to "process and interpret video segments" in multimodal agent workflows.
  • Generative video summarization: when an Azure OpenAI resource is connected to the VI account, VI can produce natural-language video summaries directly, useful as a pre-chunked grounding artifact for RAG.
Must know: For AI-103 "video analysis / multimodal" scenarios, the expected pattern is: Index video with VI → retrieve time-stamped JSON insights → index/store in Azure AI Search or a vector store → use as grounding/context for an LLM or agent, rather than sending raw video frames directly to an LLM.

10. Pricing & Tiers (Basics)

  • VI is billed based on indexing minutes processed (consumption-based), with separate rates for Basic/Standard vs. Advanced indexing presets (advanced presets run more models — e.g., detailed audio/visual insights — at higher cost).
  • A free trial account provides a limited number of free indexing minutes without an Azure subscription, portal-only, no API access.
  • Paid/standard (ARM) accounts are billed through the linked Azure subscription alongside the required Standard GPv2 storage account costs (storage + transactions) and any connected Azure OpenAI consumption (for generative summarization).
  • Video Indexer enabled by Azure Arc has its own licensing/registration process (sign-up required) distinct from the cloud SaaS billing model.
For the exam, focus on the conceptual distinction (trial vs. standard/paid, basic vs. advanced indexing presets drive cost) rather than memorizing exact per-minute prices, which change over time.
Must know: Pricing scales with indexing minutes and preset depth (basic/standard vs. advanced insights) — trial accounts are free but capped, portal-only, and cannot call the API.
